# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `startup` / top level | No database indexes were created at startup. | Queries performed collection scans (`COLLSCAN`), and duplicate inserts succeeded. | Added `@app.on_event("startup")` creating indexes on `employees` (`emp_code`, `department, emp_code`, `joined_on`) and `attendance_logs` (`emp_code, date`, `date, emp_code`, `emp_code, punch_in`), with an index hint for department summaries. |
| 2 | `health` & `MongoClient` | Returned static `{"status": "ok"}` without checking MongoDB connectivity, and driver hung for 30 seconds when down. | Returned 200 even when database stopped, or blocked request for 30s before failing. | Added `client.admin.command("ping")` raising HTTP 503 on failure, and configured `serverSelectionTimeoutMS=3000` on `MongoClient` to fail fast. |
| 3 | `punch_in` / `from_epoch_ms` (R1) | Used local system time via `datetime.now()`, kept microseconds, and ignored overnight shift dates. | Stored timestamps had microsecond noise; overnight punches before morning shift end were assigned the wrong date. | Used UTC datetimes truncated to whole seconds; mapped overnight punches before `shift_end` to `date - 1 day`. |
| 4 | `compute_late_minutes` (R2) | Checked `minutes > 10` after integer division, and mixed UTC datetimes with naive IST shift times. | A punch-in at 09:40:01 IST returned 0 late minutes instead of 10; naive datetime subtraction was offset by 5.5 hours. | Measured difference in total seconds against IST shift start, checking `diff_sec > 600` before floor dividing by 60. |
| 5 | `compute_work_hours` (R4) | Used standard Python float `round()`. | A duration of `1.005` hours rounded down to `1.00` because Python uses round-half-to-even. | Used `Decimal` quantized with `ROUND_HALF_UP` to two decimal places in a shared `round_half_up` helper. |
| 6 | `compute_overtime` (R3) | Returned overtime under 30 minutes, and did not advance the shift end day for overnight shifts. | 5 minutes past shift end returned 5 overtime minutes; overnight shift ends compared against the start day. | Calculated minutes past IST shift end (+1 day for overnight shifts) and returned 0 if under 30. |
| 7 | `compute_work_hours` / derived fields (R5) | Starter hardcoded `half_day = False` on punch-in and never computed it on punch-out. | Completed shifts under 4.50 hours were not recorded as half days. | Set `half_day = (work_hours is not None and work_hours < 4.50)`. |
| 8 | `create_employee` | Checked existence before insert without index protection, stored naive `created_at`, and returned `_id`. | Concurrent duplicate requests caused unhandled 500s; response leaked internal ObjectId and non-UTC datetimes. | Relied on the unique index, catching `DuplicateKeyError` to return 409; saved UTC datetime and returned epoch ms without `_id`. |
| 9 | `list_employees` (R10) | Pagination formula skipped the first page (`page * page_size`), total ignored query filters, and records were unsorted. | Page 1 returned items 21–40; total returned the entire collection count instead of the filtered count. | Set `skip = (page - 1) * page_size`, filtered `count_documents(q)`, added `.sort("emp_code", 1)`, and capped `page_size` at 100. |
| 10 | `EmployeeIn`, `PunchInIn` | Loose validation on email/joined_on, accepted seconds-like integers for timestamps, and rejected equal shift times. | Accepted invalid emails, impossible calendar dates (`2026-02-31`), second-like integers, and rejected valid equal shifts. | Added email regex, real calendar date validator on `joined_on`, 1–30 trimmed non-whitespace `emp_code`, permitted equal shifts per R1, and required strict epoch ms. |
| 11 | `serialize_employee`, `serialize_log` | Returned MongoDB's `_id` as `id`, returned raw datetimes, and crashed on legacy records missing `history` or `half_day`. | Response leaked internal `id`; timestamps were not epoch ms; older documents raised KeyError. | Omitted `_id`, formatted instants as epoch milliseconds, and safely defaulted `history` to `[]` and `half_day` to `False`. |
| 12 | `punch_in` error handling | Raised an unhandled `TypeError` when an employee was not found. | Punching in for a non-existent employee crashed with 500 instead of 404. | Added an initial employee lookup check raising 404 when the employee does not exist. |
| 13 | `punch_in` concurrency race | Checked for existing records with `find_one` prior to inserting. | Two simultaneous punch-ins for the same employee and date could both pass the check. | Removed check-then-insert; used atomic `insert_one` catching `DuplicateKeyError` from the unique index to return 409. |
| 14 | `punch_out` concurrency race & validation | Unconstrained `update_one` on punch-out allowed simultaneous requests to both succeed, and missing employee check raised 500. | Two concurrent punch-out requests both returned 200; punch-out for non-existent employee returned 500. | Added employee lookup check raising 404; guarded `update_one` with `{"punch_out": None}`, returning 409 if `matched_count == 0`. |
| 15 | `list_attendance` scalability | Loaded the entire collection into memory with `list()` and sorted in Python; omitted date order check. | High memory consumption and latency on 100k records; `date_from > date_to` was accepted. | Pushed sorting, skipping, and limiting down to MongoDB; added validation raising 422 when `date_from > date_to`. |
| 16 | Date & month parsing (helpers & explain) | Permissive date parsing accepted non-hyphenated formats (`20260706`), and bad month strings in explain branches raised 500s. | Queries like `date_from=20260706` or `month=abc` in explain caused unhandled 500 internal server errors. | Added `parse_date` enforcing exact `YYYY-MM-DD` and `check_month` enforcing `YYYY-MM`, raising HTTP 422 on any parsing failure. |
| 17 | `regularize_attendance` (PATCH guard & race) | Guard tested `body.status` instead of `new_status` (silently ignoring punch times on existing ABSENT/LEAVE records), and unconstrained writes caused stale-read history overwrites. | Submitting punch times without status on ABSENT records bypassed validation; concurrent PATCH calls recorded inaccurate 'from' diffs. | Checked `new_status` raising 422 for ABSENT/LEAVE with punch times; implemented compare-and-set on `(status, punch_in, punch_out)` with a single re-read retry and 409 conflict. |
| 18 | `to_epoch_ms` & `from_epoch_ms` precision | Used floating point math (`int(dt.timestamp() * 1000)` and `ms / 1000`). | Seeded timestamps carrying milliseconds suffered float precision truncation and sub-second rounding errors. | Switched to integer math: `ms // 1000` in `from_epoch_ms` and `(dt - EPOCH) // timedelta(milliseconds=1)` in `to_epoch_ms`. |
| 19 | `regularize_attendance` parameter shadowing | Path parameter named `date` shadowed Python's imported `datetime.date` class in function scope. | Accessing `date.fromisoformat` or date constructors within the route raised `AttributeError: 'str' object has no attribute 'fromisoformat'`. | Renamed function parameter to `path_date: str = Path(..., alias="date")`, preserving the path contract while unshadowing `date`. |

## Items examined and decided NOT to be defects

1. **Client supplying `emp_code`**: In `POST /employees`, the client provides `emp_code` rather than the server auto-generating it. This is intentional per specification because `emp_code` is an external business identifier assigned by HR.
2. **Dates and shift times stored as strings**: `date`, `joined_on`, `shift_start`, and `shift_end` are stored as plain strings (`"YYYY-MM-DD"`, `"HH:MM"`). This is intentional per `DATA_MODEL.md` to prevent unintended timezone conversions on calendar and time-of-day values.
3. **No endpoints for `ABSENT` / `LEAVE` creation**: There are no endpoints to create `ABSENT` or `LEAVE` records directly. This is intentional as these statuses represent seeded back-office data or manual regularizations (`PATCH`).
4. **No authentication on endpoints**: `regularized_by` in regularization is accepted as a plain string without authentication headers. This is intentional per assignment requirements.
5. **Equal `shift_start` and `shift_end`**: When `shift_start` equals `shift_end` (e.g. `09:30` to `09:30`), it represents an overnight shift under rule R1 (`shift_end <= shift_start`), which is intentionally valid.
6. **`$densify` on empty attendance stream**: When a department has employees but no attendance logs in the requested range, MongoDB's `$densify` with explicit date bounds `[from_dt, to_dt_plus_1]` generates all calendar day rows natively in the database, with headcount and zero counts, requiring no fallback logic.
